# Cookies en curl

curl tiene un motor completo de cookies que sigue RFC 6265.

## Conceptos básicos

Las cookies son pares `nombre=valor` que:
- El servidor envía al cliente en el header `Set-Cookie:`
- El cliente envía de vuelta en el header `Cookie:`
- Pueden tener atributos: `Path`, `Domain`, `Expires`, `Max-Age`, `Secure`, `HttpOnly`, `SameSite`

## Opciones principales

| Opción | Descripción |
|--------|-------------|
| `-b` / `--cookie` | Enviar cookies (string o archivo) |
| `-c` / `--cookie-jar` | Guardar cookies tras transferencia |
| `-j` / `--junk-session-cookies` | Ignorar session cookies al cargar |

## Activar el motor de cookies

El motor se activa con `-b` o `-c`. Si solo quieres que curl **entienda** cookies sin enviar ninguna:

```bash
# String vacío (no envía, pero acepta y guarda)
curl -b "" https://example.com

# Archivo inexistente (no envía)
curl -b /dev/null https://example.com
```

## Enviar cookies (opción `-b`)

### Como string inline

```bash
# Una cookie
curl -b "session=abc123" https://example.com

# Múltiples cookies
curl -b "session=abc123; user=john" https://example.com
```

### Desde archivo

```bash
# Archivo con cookies (formato Netscape o headers HTTP)
curl -b cookies.txt https://example.com
```

### Sin enviar cookies pero entendiendo

```bash
curl -b "" -c cookies.txt -L https://example.com
```

## Guardar cookies (opción `-c`)

```bash
# Tras la transferencia, guardar todas las cookies conocidas
curl -c cookies.txt https://example.com

# Guardar a stdout
curl -c - https://example.com

# Combinar lectura y escritura
curl -b cookies.txt -c cookies.txt https://example.com
```

## Flujo típico de login con cookies

```bash
# 1. Login (recibe y guarda cookies de sesión)
curl -c cookies.txt -d "user=admin&password=secret" https://example.com/login

# 2. Usar las cookies en requests subsiguientes
curl -b cookies.txt https://example.com/dashboard

# 3. Hacer requests autenticadas con la sesión
curl -b cookies.txt https://example.com/api/me
curl -b cookies.txt -X POST -d "title=hello" https://example.com/api/posts
```

## Formato del archivo de cookies

curl usa el formato **Netscape cookie file** (legacy pero aún compatible).

Cada línea es una cookie con campos separados por TAB:

```
# Domain    #IncludeSubdomains  #Path  #Secure  #Expiration  #Name  #Value
example.com  FALSE  /  TRUE  0  sessionId  abc123
.example.com TRUE  /  FALSE 1700000000  user  john
```

- **`# Netscape HTTP Cookie File`** o **`# HTTP Cookie File`**: header del archivo
- Líneas con `#` son comentarios (excepto `#HttpOnly_*` para cookies HttpOnly)
- `TRUE`/`FALSE` indica boolean
- Expiración: segundos desde epoch (0 = session cookie)

### Ejemplo de archivo válido

```
# Netscape HTTP Cookie File
# https://curl.se/docs/http-cookies.html
# This file was generated by libcurl! Edit at your own risk.

#HttpOnly_.example.com  TRUE  /  FALSE  0  session  secret123
example.com  FALSE  /  FALSE  1735689600  theme  dark
example.com  FALSE  /  TRUE  0  auth_token  xyz789
```

## Cookies de sesión vs persistentes

| Tipo | Característica |
|------|----------------|
| Sesión | Sin `Expires`/`Max-Age` → se borran al cerrar "sesión" |
| Persistente | Con `Expires`/`Max-Age` → duran hasta esa fecha |

```bash
# Ignorar session cookies al cargar (parece inicio de sesión nueva)
curl -b cookies.txt -j https://example.com
```

## Public Suffix List (PSL)

curl (si está compilado con soporte PSL) **rechaza** cookies para super domains como `.com`, `.co.uk` (evita "super cookies").

```bash
# Verificar si curl tiene PSL
curl --version
# Buscar "PSL" en features
```

## Cookies y SameSite

curl soporta el atributo `SameSite` (RFC 6265bis):
- `Strict`: solo en same-site
- `Lax`: same-site + top-level navigations
- `None`: cross-site (requiere `Secure`)

curl maneja `SameSite` automáticamente, pero el comportamiento exacto puede variar.

## Cookies y Secure

- `Secure`: cookie solo se envía sobre HTTPS
- curl trata `http://localhost` como contexto seguro (igual que navegadores)

## Debugging cookies

```bash
# Ver cookies enviadas y recibidas en headers
curl -v -b "" -c cookies.txt https://example.com 2>&1 | grep -i "cookie\|set-cookie"

# Output esperado:
# > Cookie: session=abc; user=john
# < Set-Cookie: newcookie=value; Path=/; Secure; HttpOnly
```

## Ejemplo completo: sesión de login real

```bash
#!/bin/bash
# Flujo completo: GET login form, POST credenciales, seguir session, fetch dashboard

COOKIE_JAR=/tmp/session-cookies.txt
rm -f $COOKIE_JAR

# 1. GET la página de login (puede settear CSRF token o similar)
curl -s -c $COOKIE_JAR https://example.com/login -o login.html

# 2. Extraer CSRF token del HTML
CSRF=$(grep -oP 'name="csrf_token" value="\K[^"]+' login.html)

# 3. POST las credenciales con el token
curl -s -b $COOKIE_JAR -c $COOKIE_JAR \
  -X POST \
  -d "csrf_token=$CSRF" \
  -d "username=admin" \
  -d "password=secret" \
  https://example.com/login \
  -o login-response.html

# 4. Usar la sesión autenticada
curl -s -b $COOKIE_JAR https://example.com/dashboard
curl -s -b $COOKIE_JAR https://example.com/api/user/profile
```

## Limpiar cookies

```bash
# Borrar cookie específica (con valor vacío + jar vacío)
echo "" > cookies.txt
curl -c cookies.txt -b cookies.txt https://example.com
```

## Casos especiales

### Cookie solo para Same-Site (no se envía con redirects cross-site)

```bash
# -L sigue redirects pero mantiene cookies
curl -L -b cookies.txt -c cookies.txt https://example.com
```

### Cookies con SameSite=None requieren Secure

El server debe setear:
```
Set-Cookie: tracking=xyz; Secure; SameSite=None
```

curl respeta esto.

### Múltiples cookies en `-b`

```bash
# Repetir -b acumula
curl -b "a=1" -b "b=2" https://example.com
# Equivale a:
curl -b "a=1; b=2" https://example.com
```

## Consideraciones de seguridad

1. **No commitear cookie jars** a git (contienen credenciales)
2. **Permisos del archivo**: `chmod 600 cookies.txt` (solo tú)
3. **TTL**: session cookies en el jar se borran al cerrar
4. **HttpOnly**: cookies marcadas así no son accesibles via JS, pero curl las maneja normalmente
5. **Secure cookies**: solo se envían sobre HTTPS (excepto localhost)
